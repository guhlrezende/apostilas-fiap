1Git e GitHub não são a mesma coisa

Todo mundo diz “sobe no Git” quando quer dizer “sobe no GitHub”. Dá para ser uma coisa sem a outra?

Intuição. Git é o caderno de histórico que fica no seu computador. GitHub é um prédio na internet com estantes onde você guarda cópias desses cadernos, e que ainda tem sala de reunião, quadro de tarefas e vigia na porta. O caderno funciona sem o prédio. O prédio é que não faz sentido sem os cadernos.

Definição. Git é o programa que registra o histórico de um projeto. GitHub é um serviço na nuvem que hospeda repositórios Git e acrescenta revisão de código (pull request), issues, automação (Actions), páginas, releases e controle de acesso. GitLab e Bitbucket fazem o mesmo papel; no GitLab o equivalente do pull request se chama merge request. Eu não li a documentação deles, então não detalho aqui. Os comandos git são os mesmos nos três. (Fonte: GitHub Docs e Pro Git, lidos em 10/11/2026.)

Exemplo resolvido: um repositório inteiro, sem GitHub nenhum
Numa pasta temporária nova rodei git init, escrevi um README.md e fiz um commit. Tudo funcionou: histórico, branch, log.
O git remote -v voltou vazio: o repositório não conhece nenhum endereço na internet. Ele só passa a falar com o GitHub quando você adiciona um remoto (capítulo 3).
Conclusão prática: se o GitHub sair do ar ou você ficar sem internet, o seu histórico continua inteiro no seu computador.
$ git init -b main treino
$ cd treino
$ printf '# treino\n' > README.md
$ git add . ; git commit -qm "docs: cria README"
$ git remote -v                 # nada: nenhum remoto configurado
$ git branch --show-current
main

Rodado de verdade em 10/11/2026 (Git 2.56 no Windows 11, Git Bash), em pasta temporária nova, fora do repositório. Foi um repositório local, sem remoto. Hashes, datas e caminhos mudam em cada máquina.

Erro comumAchar que “o código está seguro porque está no GitHub”, ou que “o Git é o site”. O GitHub guarda uma cópia, e quem controla o que entra nela é você (e as regras do repositório). Um git push errado também sobe errado.

2Conta, perfil, 2FA e passkey

Criar conta é só preencher um formulário. Por que a documentação insiste tanto no segundo fator?

Intuição. Sua conta é a chave do prédio inteiro: seus repositórios, os de quem te deu acesso e as chaves de publicação. Só a senha é uma tranca simples. A verificação em duas etapas (2FA) é uma segunda tranca que o ladrão de senha não tem.

Definição. A conta é criada em github.com/signup, com e-mail verificado. O nome de usuário aparece em todo commit, PR e no perfil: escolha um que você aceite mostrar em público. A 2FA aceita app autenticador (TOTP), SMS, chaves de segurança (FIDO2, Touch ID, Windows Hello) e passkeys. A página oficial recomenda uma passkey com um método reserva (TOTP ou SMS). O GitHub Mobile pode ser segundo fator, mas só depois de configurar TOTP ou SMS. Os códigos de recuperação devem ser baixados e guardados: a página avisa que o suporte não consegue restaurar a conta de quem perde o 2FA e os métodos de recuperação. A mesma página informa que, desde março de 2023, o GitHub exige 2FA de quem contribui com código no GitHub.com. (Fonte: GitHub Docs, lido em 10/11/2026.)

Não testado aquiNão criei conta nem liguei 2FA para escrever isto. Eu não descrevo as telas (nomes de menus e botões mudam): siga o assistente do próprio GitHub e confira cada método na página oficial listada nas fontes.
Erro comumLigar a 2FA e não baixar os códigos de recuperação. Se o celular some, a conta pode ficar perdida, e o suporte não a restaura. Guarde os códigos fora do aparelho que gera o segundo fator.

3O e-mail que vai em cada commit

Fiz um commit com o e-mail da minha caixa pessoal. Alguém consegue ler isso depois?

Intuição. Todo commit carrega uma etiqueta com nome e e-mail do autor, como o remetente de uma carta. Num repositório público, a carta e o remetente ficam expostos para sempre. Por isso existe um endereço de fachada: o noreply.

Definição. O GitHub associa um commit à sua conta pelo e-mail do commit, e só e-mails adicionados e verificados na conta contam. Existe a opção “Keep my email address private”; com ela, o commit feito pela interface web usa o endereço noreply da sua conta. Commits antigos continuam com o e-mail antigo: trocar a configuração não reescreve o passado (para isso seria preciso reescrever o histórico, capítulo 9). O formato exato do endereço noreply não estava na página que li: copie-o da tela de e-mails da sua conta (confira). A página também cita como bloquear pushes que exponham o e-mail pessoal, mas eu não li esse guia. (Fonte: GitHub Docs e Pro Git, lidos em 10/11/2026.)

Exemplo resolvido: o e-mail do commit fica gravado, e eu consigo ler
Para não mexer na minha configuração real, apontei GIT_CONFIG_GLOBAL para um arquivo temporário. Assim o --global só escreveu nesse arquivo.
Configurei nome, e-mail (um espaço reservado, SEU-EMAIL-NOREPLY, que você troca pelo endereço da sua conta) e init.defaultBranch main.
Depois de um commit, o git log -1 --format='%an | %ae | %s' mostrou o nome, o e-mail e a mensagem: tudo isso viaja junto com o commit.
$ git config --global user.name "Seu Nome ou Apelido"
$ git config --global user.email "SEU-EMAIL-NOREPLY"     # copie o endereco noreply da sua conta
$ git config --global init.defaultBranch main
$ git config --global --list --show-origin
file:C:/Users/voce/.gitconfig	user.name=Aluno Exemplo
file:C:/Users/voce/.gitconfig	user.email=SEU-EMAIL-NOREPLY
file:C:/Users/voce/.gitconfig	init.defaultbranch=main
$ git log -1 --format='%an | %ae | %s'
Aluno Exemplo | SEU-EMAIL-NOREPLY | docs: README, LICENSE, gitignore e templates (Closes #7)

Rodado em 10/11/2026 com um arquivo de configuração temporário. Nas máquinas, --global escreve no .gitconfig da sua pasta de usuário. Aqui o nome “Aluno Exemplo” é inventado.

Erro comumUsar o nome completo e o e-mail pessoal sem perceber, em repositório público. O que está num commit publicado não some trocando a configuração depois. Decida o nome e o e-mail antes do primeiro commit público.

Laboratório: conta e identidade

Este laboratório é na sua conta e no seu computador. Nenhum passo exige colar senha ou token em lugar nenhum.

Confira com git --version que o Git está instalado. Se for a primeira vez, rode os três git config --global do exemplo acima, com o e-mail noreply da sua conta (copiado da tela de e-mails dela).
Rode git config --global --list --show-origin e confirme que o nome, o e-mail e o init.defaultbranch aparecem. Se aparecer um e-mail pessoal onde devia estar o noreply, corrija antes do primeiro commit público.
Na sua conta, confirme que há pelo menos dois métodos de segundo fator (por exemplo passkey e app autenticador) e que você baixou os códigos de recuperação e os guardou num cofre de senhas.
Leia o seu perfil em modo anônimo (uma janela privada do navegador): o que aparece para quem não está logado? Ajuste nome e bio se algo ali você não quer mostrar.
Prova de que deu certo: um commit de teste numa pasta nova e o git log -1 --format='%an | %ae' mostram o nome e o e-mail que você escolheu, e nenhum e-mail pessoal.

4Fechamento do capítulo

Cola da prova

  • Git guarda o histórico no seu computador; GitHub hospeda repositórios Git e acrescenta PR, issues, Actions, Pages e releases. Um repositório Git funciona sem GitHub.
  • Ligue a 2FA, de preferência passkey com método reserva, e guarde os códigos de recuperação: o suporte não restaura a conta de quem perde tudo.
  • O nome de usuário e o e-mail do commit são públicos em repositório público. Use o endereço noreply da sua conta (copie da tela de e-mails; o formato exato eu não confirmei).
  • Commits antigos não mudam quando você troca a configuração.
  • git config --global --list --show-origin mostra de onde vem cada valor.

Teste rápido

Pergunta 1

Um colega diz que o projeto dele está “no Git, então está no GitHub”. Qual a correção?

Git é o programa de histórico. O GitHub é um serviço que hospeda repositórios Git. Sem git push para um remoto, nada vai para lá.
Pergunta 2

Qual combinação a página oficial de 2FA recomenda?

A mesma página avisa que o suporte não restaura a conta de quem perde o 2FA e também a recuperação.
Pergunta 3

Você trocou o e-mail da configuração do Git hoje. O que acontece com os commits de ontem?

O e-mail fica gravado em cada commit. Mudar o futuro não reescreve o passado.
Pergunta 4

Por que a apostila escreve SEU-EMAIL-NOREPLY em vez de um endereço?

Onde eu não confirmei, escrevo “confira”. Aqui, o dado certo está na sua conta.
