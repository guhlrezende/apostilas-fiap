Onde paramosNo capítulo 5 você escreveu à mão o laço de um agente: pedir ferramenta, executar, devolver. O Claude Code é esse laço pronto, com ferramentas para ler, editar e rodar comandos no seu projeto.

1Instalar e começar

Como chegar ao primeiro "claude" funcionando?

Pela documentação oficial, a instalação nativa (recomendada) é um comando:

# macOS, Linux e WSL
curl -fsSL https://claude.ai/install.sh | bash

# Windows PowerShell
irm https://claude.ai/install.ps1 | iex

# depois, em qualquer projeto
cd seu-projeto
claude

Confira com claude --version. No primeiro uso ele pede login (assinatura do Claude ou conta da Console). No Windows nativo, a documentação recomenda o Git for Windows para o Claude Code usar o Bash. A instalação nativa se atualiza sozinha; Homebrew e WinGet não.

O mesmo Claude Code roda no terminal, em extensões para VS Code (e Cursor) e JetBrains, no app desktop (aba Code) e na web (claude.ai/code). As configurações do repositório valem em todos.

2CLAUDE.md: as instruções permanentes

Onde escrever "rode o checar antes de commitar" uma vez só?

O CLAUDE.md é um arquivo Markdown que o Claude Code lê no começo de cada sessão. Há camadas, e todas são somadas (não se substituem):

CamadaOndePara
Política da organizaçãopasta do sistema gerenciada pela TIregras da empresa
Usuário~/.claude/CLAUDE.mdsuas preferências em todos os projetos
Projeto./CLAUDE.md ou ./.claude/CLAUDE.mdregras do time, no Git
Local./CLAUDE.local.md (no .gitignore)suas notas daquele projeto

/init gera um primeiro CLAUDE.md analisando o projeto. Dá para importar outros arquivos com @caminho/arquivo e separar regras por assunto em .claude/rules/, inclusive valendo só para certos caminhos. Além disso, o Claude Code mantém uma memória automática com o que aprende das suas correções.

# Projeto: apostilas de estudo

## Comandos
- Servir local: `python scripts/serve.py` (porta 4323)
- Checar antes de commit: `python scripts/checar.py`

## Regras
- Português do Brasil, sem travessão.
- Repositório público: nunca colocar nome completo, matrícula ou e-mail.
- Todo número citado no texto precisa bater com a demo. Rode e confira.

## Fluxo
- Mudança em mais de um arquivo: planeje antes (plan mode) e rode o checar no fim.
Erro comumCLAUDE.md gigante. A documentação sugere menos de 200 linhas e um teste por linha: "se eu apagar isto, o Claude erra?". Se não, apague. Regra que não pode falhar nunca vira hook (capítulo 7), porque CLAUDE.md é orientação, não trava.

3Explorar, planejar, implementar

Por que não deixar ele codar direto?

Porque ele pode resolver o problema errado. O fluxo recomendado tem quatro fases: explorar, planejar, implementar e commitar. Para as duas primeiras existe o plan mode: aperte Shift+Tab até aparecer "plan mode on" (ou inicie com claude --permission-mode plan). Nele o Claude lê e responde, mas não altera nada. Ctrl+G abre o plano no seu editor para você corrigir antes de aprovar.

Se a mudança cabe numa frase ("corrija o erro de digitação no título"), pule o plano: ele tem custo.

Permissões. No modo manual, o Claude Code pede aprovação antes de editar arquivo ou rodar comando. No auto mode (padrão nas versões recentes), um classificador revisa cada ação e bloqueia só o que parece arriscado. /permissions libera de vez comandos em que você confia, como npm run lint.

4Contexto: o recurso que acaba

Por que o Claude parece "esquecer" instruções depois de uma hora de sessão?

Tudo entra na janela de contexto: mensagens, arquivos lidos, saídas de comandos. A documentação é direta: o desempenho cai conforme ela enche. Os controles:

ComandoO que faz
Escinterrompe o Claude no meio, mantendo o contexto
Esc duas vezes ou /rewindvolta a conversa e/ou o código a um ponto anterior
/clearzera o contexto entre tarefas sem relação
/compact focoresume o histórico, guardando o que você pedir
/contextmostra o que está ocupando o contexto
claude --continue / --resumeretoma a última sessão / escolhe uma da lista
Exemplo resolvido: duas correções e nada
Você corrigiu o Claude duas vezes no mesmo ponto e ele continua errando.
O contexto está cheio de tentativas fracassadas, que puxam a resposta para o mesmo erro.
A recomendação oficial: /clear e um prompt novo, mais específico, já com o que você aprendeu. Uma sessão limpa com prompt melhor quase sempre vence.
Dê uma forma de verificarO conselho que abre o guia de boas práticas: dê ao Claude algo que ele possa rodar (testes, build, screenshot) e peça a evidência, não a afirmação.

Pergunta 1

Onde ficam as suas preferências pessoais que valem em todos os projetos?

~/.claude/CLAUDE.md é a camada do usuário. ./CLAUDE.md é do projeto; CLAUDE.local.md, suas notas de um projeto só.
Pergunta 2

Como entrar no plan mode durante a sessão?

Shift+Tab alterna os modos. Esc duas vezes abre o rewind; /clear zera o contexto.

Você quer que o Claude NUNCA edite o arquivo .env. Onde colocar isso?

CLAUDE.md orienta, mas não garante. Hook é determinístico.
