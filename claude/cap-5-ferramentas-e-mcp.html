Onde paramosNo capítulo 4 você fez o Claude responder de dentro de um programa. Mas ele só sabia o que estava no prompt. Para consultar um sistema seu, ele precisa de ferramentas.

1Como o Claude usa uma ferramenta

O Claude executa código no seu servidor? Não. Então como ele "consulta" algo?

Você descreve a ferramenta: nome, descrição (é por ela que o modelo decide usar) e input_schema (os parâmetros, em JSON Schema). Quando o pedido do usuário bate com a ferramenta, o Claude não responde texto: ele devolve stop_reason: "tool_use" e um bloco tool_use com id, name e input. O seu código executa e devolve o resultado num bloco tool_result, com o mesmo tool_use_id, numa mensagem de papel user. Aí o Claude responde.

1. Pedido

Usuário: "Qual o próximo prazo do processo 1002?" e a lista de ferramentas.

2. O Claude pede a ferramenta

stop_reason: "tool_use" e o bloco {"type":"tool_use","id":"toolu_1","name":"consultar_prazo","input":{"numero":"1002"}}.

3. O seu código executa

consultar_prazo("1002") devolve "03/12/2026".

4. Você devolve o resultado

Mensagem user com {"type":"tool_result","tool_use_id":"toolu_1","content":"03/12/2026"}.

5. O Claude responde

stop_reason: "end_turn" e o texto: "O próximo prazo é 03/12/2026."

Um laço.

2O laço do agente, em código

O que transforma uma chamada com ferramenta num agente?

Repetir: chamar, executar o que ele pedir, devolver, chamar de novo, até o stop_reason deixar de ser tool_use. Esse laço é o coração de qualquer agente, incluindo o Claude Code.

"""Claude chamando uma ferramenta sua: o laço completo (apostila do Claude, cap. 5).

O Claude não executa nada sozinho: ele PEDE a ferramenta (bloco tool_use), o seu código
executa e devolve o resultado (bloco tool_result). O laço repete até o stop_reason ser end_turn.
Rodar:  pip install anthropic   e   python ferramenta.py   (precisa de ANTHROPIC_API_KEY)
"""
import anthropic

PRAZOS = {"1001": "15/11/2026", "1002": "03/12/2026"}  # dados fictícios


def consultar_prazo(numero: str) -> str:
    """A ferramenta de verdade: aqui seria uma consulta ao seu sistema."""
    return PRAZOS.get(numero, "processo não encontrado")


FERRAMENTAS = [{
    "name": "consultar_prazo",
    "description": "Consulta o próximo prazo de um processo pelo número interno de 4 dígitos.",
    "input_schema": {
        "type": "object",
        "properties": {"numero": {"type": "string", "description": "Número interno, ex.: 1001"}},
        "required": ["numero"],
    },
}]


def conversar(pergunta: str, cliente: anthropic.Anthropic) -> str:
    mensagens = [{"role": "user", "content": pergunta}]
    while True:
        resp = cliente.messages.create(
            model="claude-sonnet-5-5", max_tokens=500, tools=FERRAMENTAS, messages=mensagens,
        )
        if resp.stop_reason != "tool_use":                 # terminou: devolve o texto
            return "".join(b.text for b in resp.content if b.type == "text")
        mensagens.append({"role": "assistant", "content": resp.content})
        resultados = []
        for bloco in resp.content:                         # pode vir mais de um pedido
            if bloco.type == "tool_use" and bloco.name == "consultar_prazo":
                resultados.append({
                    "type": "tool_result",
                    "tool_use_id": bloco.id,               # liga o resultado ao pedido certo
                    "content": consultar_prazo(**bloco.input),
                })
        mensagens.append({"role": "user", "content": resultados})


if __name__ == "__main__":
    print(conversar("Qual o próximo prazo do processo 1002?", anthropic.Anthropic()))

Ferramentas de servidor.

3Ferramentas de cliente e de servidor

Para buscar na web, preciso escrever a busca?

Não. A documentação separa dois tipos. Ferramentas de cliente rodam na sua aplicação: as que você define, e algumas com formato da Anthropic, como bash e text_editor. Ferramentas de servidor rodam na infraestrutura da Anthropic e o resultado já volta na resposta: web_search, web_fetch, code_execution e tool_search. A busca na web, por exemplo, tem cobrança por pesquisa além dos tokens.

MCP.

4MCP: um padrão para ferramentas

Como uma ferramenta escrita uma vez funciona no app, no Claude Code e em outros clientes?

O Model Context Protocol (MCP) é um padrão aberto para ligar aplicações de IA a fontes de dados e ferramentas. Quem tem os dados publica um servidor MCP (Notion, Google Drive, Jira, o seu banco); quem usa a IA conecta um cliente MCP. A ferramenta é descrita uma vez e qualquer cliente compatível usa.

ConfiançaUm servidor MCP lê dados e pode agir em seu nome. Instale só de quem você confia, e trate o que vem dele como dado, não como ordem: um documento malicioso pode conter instruções escondidas (prompt injection).

5Fechamento do capítulo

Cola da prova

  • Ferramenta = nome + descrição + input_schema. A descrição decide quando ela é usada.
  • tool_use (id, name, input) pede; o seu código executa; tool_result com o mesmo id devolve, em mensagem user.
  • Agente = laço até stop_reason deixar de ser tool_use.
  • Cliente roda na sua aplicação; servidor (web_search, web_fetch, code_execution) roda na Anthropic.
  • MCP: padrão aberto; servidor publica, cliente consome. Cuidado com prompt injection.
