Onde paramosNo Capítulo 2 você desenhou a startup alpha: funcionário e projeto em N:N, projeto ligado a um único programa. Mas era um desenho. Falta transformar isso em tabelas com tipos de dados, chaves e regras que o banco faça valer sozinho. É o modelo lógico e a DDL.

1Três problemas concretos

Desenhar é fácil. Impedir que alguém grave lixo é outra história.

A alpha precisa alocar funcionários em projetos e pagar por hora trabalhada. Isso levanta três perguntas que toda modelagem lógica responde:

  1. Que tipo de dado cada campo deve ter (data, número, texto)?
  2. Como garantir que ninguém insira dado inválido (funcionário sem CPF, projeto sem data)?
  3. Como criar de fato as tabelas?

A grande ideia da aula: as regras de negócio podem morar no próprio banco, e não só na aplicação. Assim nenhum programa, nem um script mal escrito, nem um acesso direto consegue burlá-las.

Para onde vamos agora
Quais são essas regras que o banco sabe impor?

As restrições (constraints), e duas chaves que sustentam o relacionamento entre tabelas.

2Chaves e restrições

PK, FK e cinco regras que cabem numa linha cada.

Chave primária (PK)

Identifica unicamente cada registro da própria tabela. Só existe uma por tabela, mas pode ser composta por mais de uma coluna, como PRIMARY KEY (idProjeto, idFuncionario) na tabela associativa.

Chave estrangeira (FK)

É uma coluna que referencia a PK de outra tabela. É o mecanismo do relacionamento: impede, por exemplo, uma alocação para um projeto que não existe. Isso se chama integridade referencial.

3Tipos de dados

Tudo cabe em texto. Por que não usar só VARCHAR?

Porque o tipo define quanto espaço o dado usa e que operações fazem sentido (somar datas, comparar números). No MySQL, os principais:

GrupoTiposObservação
InteirosTINYINT (1 byte), SMALLINT (2), MEDIUMINT (3), INT (4), BIGINT (8)TINYINT vai de -128 a 127 (ou 0 a 255 sem sinal). Por isso horas na alpha é tinyint: cabe de sobra.
DecimaisFLOAT, DECIMAL, NUMERICDECIMAL(10,2) é o padrão para dinheiro (exato, sem erro de arredondamento binário).
Data e horaDATE, TIME, DATETIME, TIMESTAMP, YEARNo MySQL 8 o modo padrão recusa datas "zeradas" como 0000-00-00.
TextoCHAR(n), VARCHAR(n), TEXTVeja a comparação abaixo.

CHAR x VARCHAR

CHAR(4) sempre ocupa 4 bytes (completa com espaços). VARCHAR(4) ocupa o tamanho do texto mais 1 byte. Por isso VARCHAR é melhor para textos de tamanho variável, e CHAR para valores de tamanho fixo (CPF de 11 dígitos, sigla de estado).

'ab'4 bytes3 bytes
'abcd'4 bytes5 bytes

Com tipos e regras na cabeça, como se escreve a tabela inteira?

Com CREATE, e depois ALTER quando a estrutura precisar mudar.

4DDL: criar e alterar a estrutura

DDL define a estrutura. DML mexe nos dados. Não confunda.

DDL (Data Definition Language)

Define a estrutura: CREATE, ALTER, DROP. Usada uma vez, ou quando a estrutura muda.

DML (Data Manipulation Language)

Manipula os dados dentro da estrutura: INSERT, UPDATE, DELETE, SELECT. É o que você usa o tempo todo. (Capítulo 4.)

Este é o DDL da alpha, a versão corrigida do que o slide mostra. A tabela do meio é a associativa do N:N, com PK composta e duas FKs:

CREATE TABLE Projeto (
  idProjeto INTEGER PRIMARY KEY AUTOINCREMENT,
  sigla     VARCHAR(10) NOT NULL,
  dtInicio  DATE,
  dtTermino DATE
);
CREATE TABLE Funcionario (
  idFuncionario INTEGER PRIMARY KEY AUTOINCREMENT,
  CPF           VARCHAR(11) NOT NULL UNIQUE,
  nome          VARCHAR(50) NOT NULL,
  sobrenome     VARCHAR(50) NOT NULL,
  email         VARCHAR(50),
  habilidades   TEXT
);
CREATE TABLE ProjetoFuncionario (
  idProjeto     INT NOT NULL,
  idFuncionario INT NOT NULL,
  horas         INT,
  dtInicio      DATE,
  dtTermino     DATE,
  ativo         INT,
  PRIMARY KEY (idProjeto, idFuncionario),
  FOREIGN KEY (idProjeto)     REFERENCES Projeto(idProjeto),
  FOREIGN KEY (idFuncionario) REFERENCES Funcionario(idFuncionario)
);

Integridade referencial na prática

Agora uma base com as FKs declaradas. Tente apagar um projeto que tem alocações, e depois alocar alguém que não existe:

-- 1) apagar um projeto que tem alocações
DELETE FROM Projeto WHERE idProjeto = 3;
-- 2) alocar um funcionário que não existe
INSERT INTO ProjetoFuncionario (idFuncionario, idProjeto, ativo, horas) VALUES (999, 1, 1, 4);

No MySQL as mensagens são ERROR 1451 (não dá para apagar a linha-pai) e ERROR 1452 (a linha-pai não existe). O banco defendeu a consistência sem você escrever uma linha de validação.

Complemento: CHECK ou TRIGGER?As duas impõem regras, mas de jeitos diferentes. O CHECK é declarativo e olha só a própria linha ("idade >= 18"). Já o trigger (Capítulo 7) é imperativo: pode consultar outras tabelas e ter efeitos colaterais, mas é mais difícil de manter. A regra prática: use CHECK quando der, e trigger só quando o CHECK não alcançar.
Complemento: AUTO_INCREMENT expostoUsar o número sequencial como identificador visível numa API (/cliente/17) deixa o sistema previsível: quem vê o 17 tenta o 18, e se faltar checagem de permissão acessa dados alheios. Em APIs públicas se costuma expor um identificador aleatório (como UUID) e guardar o sequencial só por dentro.

5Fechamento do capítulo

Cola da prova

  • Modelo lógico define como os dados são guardados: tabelas, tipos, chaves e relacionamentos.
  • PK identifica a linha (pode ser composta). FK referencia a PK de outra tabela e garante a integridade referencial.
  • Restrições: NOT NULL, DEFAULT, UNIQUE, CHECK e AUTO_INCREMENT. Regras no banco ninguém burla.
  • DDL = estrutura (CREATE, ALTER, DROP). DML = dados (INSERT, UPDATE, DELETE, SELECT).
  • CHAR tem tamanho fixo; VARCHAR ocupa o tamanho do texto mais 1 byte.
  • N:N vira tabela associativa com PK composta e duas FKs.

Teste rápido

Pergunta 1

Para que serve uma chave estrangeira?

A identificação única é papel da PK. A FK cria o relacionamento e protege a integridade referencial (as mensagens 1451 e 1452 do MySQL).
Pergunta 2

Por que a PK da tabela ProjetoFuncionario é composta por (idProjeto, idFuncionario)?

Um funcionário está em vários projetos e um projeto tem vários funcionários, então nenhum id sozinho é único. O par é.
Pergunta 3

Qual comando é DDL?

ALTER muda a estrutura (DDL). UPDATE e INSERT manipulam os dados (DML).
