1CRUD: as quatro operações

Quatro verbos resolvem quase todo sistema.

DML (Data Manipulation Language) é a parte do SQL que altera e consulta os dados. Todo o CRUD sai dela:

CRUDComandoFaz
CreateINSERTinclui uma linha
ReadSELECTconsulta (o slide escreve "Request", o nome comum é Read)
UpdateUPDATEaltera linhas existentes
DeleteDELETEexclui linhas

As quatro perguntas da aula, e a resposta de cada uma: incluir e consultar funcionários (INSERT e SELECT); filtrar por habilidades (WHERE com LIKE, AND, OR); atualizar habilidades (UPDATE); filtrar projetos por período (BETWEEN).

Cuidado: SQLite x MySQLOs exemplos rodam no navegador (SQLite). Três diferenças aparecem neste capítulo: NOW() vira datetime('now'), CONCAT(a, b) vira a || b, e DATE_SUB(d, INTERVAL 35 DAY) vira date(d, '-35 day'). O resto (INSERT, SELECT, WHERE, LIKE, BETWEEN) é igual.

2INSERT: incluir

Você diz em que colunas e com que valores. O resto o banco completa.

INSERT INTO tabela (coluna1, coluna2, ...) VALUES (valor1, valor2, ...);

O idFuncionario não aparece na lista: o AUTO_INCREMENT gera sozinho. Rode e depois tente inserir uma segunda pessoa com o mesmo CPF (como faz o slide):

INSERT INTO Funcionario (CPF, nome, sobrenome, habilidades, email)
VALUES ('98765432110', 'Luana', 'Santos', 'python, sql, aws', 'luana@email.com');
SELECT idFuncionario, nome FROM Funcionario WHERE CPF = '98765432110';
INSERT INTO Funcionario (CPF, nome, sobrenome, habilidades, email)
VALUES ('12345678901', 'Alice', 'Pereira', 'python, sql, aws, mongodb', 'alice@email.com');

O banco recusou por causa do UNIQUE do CPF (no MySQL: ERROR 1062 Duplicate entry). No slide, o segundo INSERT repete o CPF da Luana de propósito, ou por descuido, e também usa uma aspa tipográfica (’) no lugar da aspa simples, o que dá erro de sintaxe antes mesmo da checagem. Cuidado ao copiar código de slide.

3SELECT: consultar, filtrar, ordenar

Quais colunas, de quais tabelas, sob quais condições.

SELECT colunas FROM tabelas WHERE condição ORDER BY coluna LIMIT n;
  • * traz todas as colunas.
  • WHERE filtra as linhas.
  • ORDER BY ordena. O padrão é crescente (ASC); DESC inverte.
  • LIMIT n corta o resultado em n linhas.
SELECT nome, sobrenome FROM Funcionario ORDER BY sobrenome DESC LIMIT 3;

O resultado traz Camila Teixeira, Rodrigo Tavares e Carlos Souza.

Erro comumAchar que LIMIT 1 devolve "o primeiro". Sem ORDER BY, o SQL não garante ordem nenhuma. Na prática o MySQL costuma devolver pela chave primária, mas isso é detalhe de implementação. Para pegar "o primeiro" de verdade, ordene.

Operadores de comparação e lógicos

OperadorSignificado
=igual
<> (ou !=)diferente
> >= < <=maior, maior ou igual, menor, menor ou igual (a tabela do slide esqueceu > e <)
AND / ORE, OU entre condições
BETWEEN a AND bentre a e b, incluindo os dois extremos
LIKEfiltra parte de um texto; % significa "qualquer coisa"

O slide define "alocação integral" como acima de 4 horas e "parcial" como até 6. Confira quantas linhas cada uma devolve:

SELECT * FROM ProjetoFuncionario WHERE horas > 4;
SELECT * FROM ProjetoFuncionario WHERE horas <= 6;

17 + 12 = 29, mas a tabela só tem 21 alocações. Oito linhas (as de 5 e 6 horas) aparecem nas duas listas: os critérios do slide se sobrepõem. Para separar de verdade, o corte tem de ser o mesmo número (por exemplo > 6 e <= 6).

LIKE: poderoso e traiçoeiro

SELECT nome, habilidades FROM Funcionario WHERE habilidades LIKE 'sql%';
SELECT nome, habilidades FROM Funcionario WHERE habilidades LIKE '%sql%';

'sql%' devolve 10 pessoas, '%sql' (termina com) devolve 2 e '%sql%' devolve 18. Duas pegadinhas que o slide não avisa:

  1. O LIKE não diferencia maiúscula de minúscula nessa base (no MySQL isso depende da collation): 'sql%' acha "SQL Server".
  2. Ele procura texto, não palavra. Procurar '%sql%' acha também "MySQL" e "PostgreSQL". Filtrar habilidade com LIKE numa coluna de texto separado por vírgula é impreciso. O jeito certo é uma tabela de habilidades ligada ao funcionário (é a 1FN do Capítulo 1 cobrando a conta).
UPDATE Funcionario SET habilidades = habilidades || ', aws' WHERE idFuncionario = 1;
INSERT INTO Funcionario (CPF, nome, sobrenome, habilidades, email)
VALUES ('98765432110', 'Luana', 'Santos', 'python, sql, aws', 'luana@email.com');
SELECT idFuncionario, nome, habilidades FROM Funcionario
WHERE habilidades LIKE '%aws%' AND habilidades LIKE '%sql%';

O resultado de AND depende do que os comandos anteriores deixaram: na base original, ninguém tem "aws", e ele devolveria 0 linhas. O estado do banco muda o que a consulta responde.

Para onde vamos agora
E se eu quiser mudar ou apagar? Qual a diferença de errar um SELECT e errar um UPDATE?

Errar um SELECT custa uma releitura. Errar um UPDATE custa dados.

4UPDATE e DELETE: o poder do WHERE

Um comando de duas palavras que pode acabar com sua tabela.

UPDATE
UPDATE Funcionario
SET habilidades = 'python, sql'
WHERE idFuncionario = 1;
DELETE
DELETE FROM Projeto
WHERE idProjeto = 3;
Erro comumEsquecer o WHERE. Sem ele, o UPDATE muda todas as linhas, e o DELETE apaga todas. Escreva o WHERE primeiro, ou confira com um SELECT usando a mesma condição antes de rodar. (O MySQL Workbench tem o modo safe updates, que recusa UPDATE e DELETE sem WHERE com chave.)

O DELETE do slide apaga o projeto 3 (NeuralNet), que tem 3 alocações. O que acontece depende de a FK existir. Na base do script da aula, que não declara FK, apaga e deixa alocações órfãs. Rode e conte:

DELETE FROM Projeto WHERE idProjeto = 3;
SELECT COUNT(*) AS alocacoes_orfas FROM ProjetoFuncionario WHERE idProjeto = 3;

As 3 alocações continuam apontando para um projeto que não existe. Com as FKs do Capítulo 3, o mesmo DELETE seria bloqueado. Por isso integridade referencial importa.

LembraO AUTO_INCREMENT não reaproveita número apagado: se você apaga o funcionário 26, o próximo recebe 27. E use o CPF (ou outra chave natural) no WHERE quando não souber o id gerado.

BETWEEN e datas (e a armadilha do slide)

SELECT nome, dtTermino FROM Projeto WHERE dtTermino BETWEEN '2026-09-17' AND '2026-09-30';

Só o MobileApp (término em 20/09) cai no intervalo. O BETWEEN é inclusivo nos dois extremos. Já o UPDATE do slide tem um problema de lógica: ele faz SET dtInicio = NOW(), dtTermino = DATE_SUB(dtInicio, INTERVAL 35 DAY). O MySQL executa os SET da esquerda para a direita, então o dtInicio já é o novo, e o término fica 35 dias antes do início. Provavelmente a intenção era 35 dias depois (DATE_ADD).

5Exercícios do slide, com solução (as soluções são de estudo: complemento)

Tente você antes de abrir. Depois confira.

Exercício: (a) inserir um registro seu com as habilidades aws, mysql; (b) acrescentar mariadb às habilidades, sem perder as que já tinha; (c) listar quem tem mariadb; (d) excluir o seu registro.

-- (a)
INSERT INTO Funcionario (CPF, nome, sobrenome, habilidades, email)
VALUES ('00000000001', 'Seu', 'Nome', 'aws, mysql', 'teste@exemplo.com');
-- (b) concatenar mantém o que já havia (no MySQL: CONCAT(habilidades, ', mariadb'))
UPDATE Funcionario SET habilidades = habilidades || ', mariadb' WHERE CPF = '00000000001';
-- (c)
SELECT idFuncionario, nome, habilidades FROM Funcionario WHERE habilidades LIKE '%mariadb%';
Por que usar o CPF no WHERE?
O id é gerado pelo banco, e você não sabe qual foi. O CPF você mesmo informou, e é UNIQUE.
Assim o UPDATE e o DELETE miram exatamente uma linha.

Exercício extra (slide 21; a resposta é complemento): "projetos do mês atual". A frase é ambígua, e vale responder as duas leituras: projetos que terminam no mês (MONTH(dtTermino) = MONTH(CURDATE()) no MySQL), ou projetos em andamento em algum dia do mês, que é dtInicio <= fim_do_mês AND dtTermino >= início_do_mês. Para setembro de 2026, a segunda leitura devolve 7 projetos:

SELECT nome FROM Projeto
WHERE dtInicio <= '2026-09-30' AND dtTermino >= '2026-09-01';

6Fechamento do capítulo

Cola da prova

  • CRUD = INSERT, SELECT, UPDATE, DELETE. É a DML.
  • SELECT cols FROM tab WHERE cond ORDER BY col LIMIT n. Sem ORDER BY, a ordem não é garantida.
  • BETWEEN é inclusivo. LIKE com % busca texto, não palavra.
  • UPDATE/DELETE sem WHERE afetam a tabela inteira. Teste a condição com SELECT antes.
  • Sem FK, o DELETE deixa linhas órfãs. Com FK, o banco bloqueia.
  • Duas condições com cortes diferentes (> 4 e <= 6) podem se sobrepor.

Teste rápido

Pergunta 1

Você roda UPDATE Funcionario SET email = 'x@exemplo.com'; sem WHERE. O que acontece?

O SQL não exige WHERE. Sem ele, o comando age em todas as linhas. Por isso se escreve (ou se testa com SELECT) a condição primeiro.
Pergunta 2

horas BETWEEN 4 AND 6 equivale a:

BETWEEN inclui os dois extremos. As alternativas a e b deixam valores de fora.
Pergunta 3

Por que LIKE '%sql%' não é um bom filtro de 'sabe SQL'?

O LIKE não conhece 'palavras'. O ideal é uma tabela de habilidades ligada ao funcionário.
