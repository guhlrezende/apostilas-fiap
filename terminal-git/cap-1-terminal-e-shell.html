1Terminal, shell e prompt

Tudo que eu faço com o mouse tem botão. Então por que gente que trabalha com programação ainda digita comando?

Intuição. Pense num balcão de atendimento. O terminal é o balcão (a janela onde você escreve e lê). O shell é o atendente do outro lado: ele lê o seu pedido, entende e chama o programa certo. Dá para trocar de atendente sem trocar de balcão, e cada atendente fala um dialeto.

Definição. Terminal é o programa de janela que mostra texto e recebe o que você digita. Shell é o programa que interpreta cada linha e executa. O prompt é o texto que aparece antes do cursor, avisando que o shell está esperando e, quase sempre, em qual pasta você está. Bash e PowerShell são shells diferentes.

No Windows 11 você vai encontrar dois que importam aqui. O Git Bash é o bash (o shell clássico do Linux) que vem junto com o Git for Windows. O PowerShell é o shell da própria Microsoft. Os dois resolvem os mesmos problemas, de jeitos diferentes:

Git Bash (bash)PowerShell

Atalhos curtossão os próprios comandosls e cat existem, mas são apelidos (alias) de Get-ChildItem e Get-Content
Exemplo resolvido: lendo uma linha de comando
Digite ls -la projeto. O shell corta a linha nos espaços: saem 3 pedaços.
O primeiro é o nome do comando (ls). O segundo, -la, são opções: duas coladas, -l (lista longa) e -a (inclui os escondidos). O terceiro, projeto, é o argumento: sobre o que agir.
Aspas juntam palavras. echo oi mundo mostra oi mundo (o shell entregou 2 argumentos e o echo separou com 1 espaço). Já echo "oi mundo" mostra oi mundo: as aspas fazem de tudo isso 1 argumento, e os espaços ficam.
$ ls -la projeto     # nome (ls) + opções (-la) + argumento (projeto)
$ echo oi    mundo
oi mundo
$ echo "oi    mundo"
oi    mundo
PS> Get-ChildItem -Force projeto     # o mesmo pedido no PowerShell (-Force inclui os escondidos)
Erro comumDigitar um comando de um shell no outro. Get-ChildItem no Git Bash devolve bash: Get-ChildItem: command not found (o mesmo tipo de aviso que você vê para qualquer comando que o bash não conhece). O caminho inverso também falha: o grep não é comando do PowerShell. No meu computador ele rodou, mas só porque a pasta usr\bin do Git estava no PATH. Tirei essa pasta do PATH da sessão e o PowerShell respondeu O termo 'grep' não é reconhecido como nome de cmdlet, função, arquivo de script ou programa operável. Não conte com isso. Confira o prompt para saber em que janela você está.

Separar terminal de shell é a forma usual de explicar. A IBM descreve o bash e a história dos shells (Bourne, csh, ksh, bash), mas não separa as duas ideias com essas palavras. Sobre PowerShell e Git Bash a IBM não tem nada nas páginas que li: essa parte é minha, testada, mais a documentação da Microsoft.

2Onde estou: pastas e caminhos

Abri o terminal e ele não mostra pasta nenhuma. Em qual pasta estou, e como me mudo?

Intuição. O terminal sempre está dentro de uma pasta, como o Explorador de Arquivos quando você abre uma. Essa é a pasta atual. Todo comando que você dá, sem dizer o contrário, age ali.

Definição. pwd mostra a pasta atual. cd muda de pasta. Um caminho absoluto começa na raiz (/c/Users/voce) e vale de qualquer lugar. Um caminho relativo começa na pasta atual (projeto). Três atalhos: . é a pasta atual, .. é a pasta de cima e ~ é a sua pasta pessoal.

TarefaGit BashPowerShell
Onde estou?pwdGet-Location (apelido pwd)
Entrar numa pastacd projetoSet-Location projeto (apelido cd)
Listarls, ls -laGet-ChildItem, Get-ChildItem -Force
Exemplo resolvido: andando por pastas
Começo em /c/Users/voce/estudo. pwd confirma.
cd projeto entra numa subpasta. O pwd agora termina em /estudo/projeto.
cd .. sobe um nível (volto para estudo). cd ~ vai direto para a pasta pessoal: /c/Users/voce.
No Git Bash, /c/ é o disco C:. Por isso /c/Users/voce e C:\Users\voce são o mesmo lugar escrito de dois modos.
$ pwd
/c/Users/voce/estudo
$ cd projeto
$ pwd
/c/Users/voce/estudo/projeto
$ cd ..              # sobe um nível
$ cd ~               # vai para a sua pasta pessoal
$ pwd
/c/Users/voce
PS> Set-Location projeto
PS> (Get-Location).Path     # o caminho como texto simples
C:\Users\voce\estudo\projeto

Nas saídas mostradas, troquei meu nome de usuário do Windows por voce. Datas, tamanhos e contagens são os da execução real. Hashes de commit mudam a cada pessoa.

Erro comumCaminho com espaço sem aspas. Se existe a pasta Meus Documentos, cd Meus Documentos dá cd: too many arguments no bash: o shell entregou 2 argumentos. No PowerShell o erro é parecido: rodei e veio Não é possível localizar um parâmetro posicional que aceite o argumento 'Documentos' (um parâmetro sobrando). O conserto é o mesmo nos dois: cd "Meus Documentos". Aprendi isso rodando: com aspas, o pwd terminou em /Meus Documentos.

3Criar, copiar, mover e apagar

Sei chegar na pasta. Agora preciso mexer no que tem dentro dela, sem o mouse.

Intuição. São os mesmos gestos do Explorador de Arquivos: criar pasta, copiar, recortar e colar (mover), renomear, apagar e abrir para ler. A diferença é que cada gesto vira uma palavra. Mover e renomear são o mesmo comando: renomear é mover para o mesmo lugar com outro nome.

GestoGit BashPowerShell
Criar pastamkdir -p a/bNew-Item -ItemType Directory -Force a\b
Criar arquivo vaziotouch notas.txtNew-Item -ItemType File notas.txt
Copiarcp origem destinoCopy-Item origem destino (apelido cp)
Mover ou renomearmv origem destinoMove-Item origem destino (apelido mv)
Apagarrm arq, rm -r pastaRemove-Item arq, Remove-Item -Recurse pasta (apelido rm)
Ler o arquivocat arqGet-Content arq
Primeiras / últimas linhashead -n 2 arq, tail -n 1 arqGet-Content arq -TotalCount 2, Get-Content arq -Tail 1
Contar linhaswc -l arq(Get-Content arq).Count
Exemplo resolvido: arrumando a pasta e contando
mkdir -p projeto/src cria projeto e src de uma vez (o -p cria o caminho inteiro). touch projeto/src/main.py cria um arquivo vazio lá dentro.
cp tarefas.txt projeto/ copia. Depois mv projeto/tarefas.txt projeto/lista.txt renomeia a cópia. O ls projeto mostra lista.txt e src.
wc -l vendas.csv responde 6: 1 linha de cabeçalho mais 5 linhas de venda. O PowerShell dá o mesmo número com (Get-Content vendas.csv).Count.
rm projeto falha com Is a directory: para pasta é preciso -r. O erro me protegeu de um descuido.
$ mkdir -p projeto/src                  # -p: cria o caminho inteiro
$ touch projeto/src/main.py             # arquivo vazio
$ cp tarefas.txt projeto/               # copia para dentro da pasta
$ mv projeto/tarefas.txt projeto/lista.txt   # renomear = mover com outro nome
$ ls projeto
lista.txt  src
$ wc -l vendas.csv
6 vendas.csv
$ rm projeto
rm: cannot remove 'projeto': Is a directory
$ rm -r projeto/src                     # -r: apaga a pasta e o que tem dentro
PS> (Get-Content vendas.csv).Count      # as 6 linhas
6
PS> Get-Content log.txt -TotalCount 2   # as 2 primeiras linhas
10:01 INFO login ana
10:03 ERRO disco cheio
Erro comumAchar que dá para desfazer. No terminal, apagar costuma ser definitivo: não testei se o rm do Git Bash ou o Remove-Item mandam algo para a Lixeira do Windows, então trate como se não mandassem. Antes de qualquer rm -r, rode ls na pasta e confira o que vai embora. E nunca digite rm -r com um caminho que você não leu duas vezes.

E quando eu esqueço o comando?

Nos dois shells há ajuda embutida. No Git Bash, ls --help mostra o uso (rodei: a primeira linha é Usage: ls [OPTION]... [FILE]...). O man ls, que as páginas de Linux mencionam, não existe no Git Bash: rodei e veio command not found. No PowerShell, Get-Help Get-ChildItem mostra a sintaxe.

Agora é a sua vez. Este terminal é um simulador com arquivos falsos (os mesmos tarefas.txt, vendas.csv e log.txt dos exemplos). Ele entende os comandos desta apostila, não o PowerShell.

4Fechamento do capítulo

Cola da prova

  • Terminal é a janela. Shell interpreta e executa. Prompt mostra que está pronto e, em geral, a pasta atual.
  • Git Bash (bash) e PowerShell resolvem o mesmo problema com dialetos diferentes. Confira o prompt antes de digitar.
  • Comando = nome + opções + argumentos, separados por espaço. Aspas juntam em um só argumento.
  • pwd/Get-Location, cd/Set-Location, ls/Get-ChildItem. Caminho absoluto x relativo; ., .. e ~.
  • mkdir, touch, cp, mv (também renomeia), rm (sem volta), cat, head, tail, wc -l.
  • Caminho com espaço pede aspas. Apagar é definitivo: ls antes de rm -r.

Teste rápido

Pergunta 1

Na linha ls -la projeto, qual é o argumento?

ls é o nome do comando, -la são opções e projeto é o argumento: sobre o que o comando age.
Pergunta 2

Você está em /c/Users/voce/estudo/projeto e digita cd ... Onde fica?

.. é a pasta de cima, um nível só. Para ir direto à pasta pessoal seria cd ~.
Pergunta 3

Por que cd Meus Documentos dá erro, e como se conserta?

O espaço separa argumentos. As aspas fazem do nome inteiro um argumento só.
