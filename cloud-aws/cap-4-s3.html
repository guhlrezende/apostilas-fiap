1S3: objetos, não máquinas

Aqui não existe sistema operacional para cuidar.

O S3 (Simple Storage Service) é um serviço de armazenamento de objetos. Dois conceitos:

  • Bucket: o contêiner dos objetos. O nome precisa ser globalmente único em toda a AWS (não só na sua conta).
  • Objeto: um par chave-valor: qualquer arquivo (HTML, imagem, CSV, JSON), endereçado por uma chave (o "caminho" no bucket). Cada objeto tem uma URL única: https://nome-do-bucket.s3.regiao.amazonaws.com/arquivo.
LimitaçãoNão existe edição parcial de um objeto. Para mudar uma linha de um CSV, é preciso substituir o objeto inteiro. (Complemento: o versionamento do S3 guarda as versões anteriores, o que evita perder o arquivo antigo ao substituir.)

O ponto central da aula é uma mudança de modelo mental: dá para publicar um site estático sem nenhuma máquina virtual. O "servidor" é o próprio serviço de armazenamento. Complemento: para o bucket se comportar como site, com um documento padrão (como o index.html), ainda se ativa o recurso de hospedagem de site estático; sem ele, a URL do objeto abre o arquivo, mas não funciona como site.

2Publicar um site: as duas camadas

Destravar a porta não é abrir a porta.

  1. Criar o bucket: escolha a região e um nome único.
  2. Desbloquear o acesso público: por padrão a AWS bloqueia todo acesso público de um bucket novo, como proteção contra exposição acidental. Você desmarca e confirma que sabe do risco.
  3. Fazer o upload do index.html.
  4. Testar a URL: ainda dá AccessDenied!
  5. Editar a política do bucket com um JSON que autoriza a leitura pública dos objetos.
  6. Testar de novo: agora o site abre.
{
  "Version": "2012-10-17",
  "Statement": [{
    "Principal": {"AWS": "*"},               // qualquer pessoa
    "Effect": "Allow",
    "Action": ["s3:GetObject"],         // só ler objetos
    "Resource": ["arn:aws:s3:::meu-bucket/*"]  // todos os objetos do bucket
  }]
}

Por que o passo 5 é necessário, se o 2 já "liberou"? Porque desbloquear só remove uma trava que impediria políticas públicas de funcionar. Não concede acesso. São duas camadas independentes: uma destrava a porta, a outra a abre. Combine as duas e veja o resultado:

Quanto isso custa? E como se compara a EBS e EFS?

Cobrança, e uma tabela de três armazenamentos.

3Cobrança e EBS x EFS x S3

Três armazenamentos que não são concorrentes.

Cobrança do S3: paga-se pelo GB armazenado por mês, pela transferência para fora da AWS e pelas solicitações (PUT, COPY, POST, LIST, GET). Não se paga por transferências dentro do S3, nem do S3 para o CloudFront ou para uma EC2 na mesma região. É um modelo parecido com o do Google Drive: você paga pelo espaço usado, não por uma máquina rodando.

Resposta à segunda pergunta do cenário: para distribuir um conjunto de dados de treino entre equipes, o S3. Para várias instâncias editarem os mesmos arquivos ao mesmo tempo, o EFS.

Complemento: CloudFrontPara sites com visitantes no mundo todo, costuma-se colocar o CloudFront (uma CDN, rede de distribuição de conteúdo) na frente do bucket: ele guarda cópias perto dos usuários, reduzindo a latência, e permite HTTPS com um domínio próprio.

4Fechamento do capítulo

Cola da prova

  • S3 guarda objetos em buckets (nome único global). Sem SO, sem servidor para cuidar.
  • Não há edição parcial: substitui-se o objeto inteiro.
  • Site estático no S3: desbloquear o acesso público e ter uma política do bucket que autorize s3:GetObject. São duas camadas.
  • Cobrança: GB armazenado, tráfego para fora e solicitações. Dentro da mesma região, para EC2 ou CloudFront, não.
  • EBS: disco de uma instância. EFS: arquivos compartilhados (Linux). S3: objetos, por URL.

Teste rápido

Pergunta 1

Você desmarcou o bloqueio de acesso público e o site ainda dá AccessDenied. O que falta?

Desbloquear só remove a trava. A autorização vem da política do bucket.
Pergunta 2

Qual serviço escolher para várias instâncias EC2 Linux editarem os mesmos arquivos ao mesmo tempo?

O EBS é anexado a uma instância por vez, e o S3 não é um sistema de arquivos montável. O EFS é o sistema de arquivos compartilhado.
Pergunta 3

Qual a grande vantagem do S3 sobre uma EC2 para um site estático?

O S3 serve os arquivos direto. Para executar código no servidor (aplicações dinâmicas), a EC2 continua sendo necessária.
