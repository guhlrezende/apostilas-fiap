Um banco MySQL na nuvem sem servidor para administrar, e por que abrir a porta ao mundo é um risco.

Onde paramosNo Capítulo 4 o S3 resolveu os arquivos sem servidor. A startup também precisa guardar dados num banco relacional, com segurança. Instalar e manter o banco numa EC2 sai caro e dá trabalho. Duas perguntas: como criar um banco na nuvem sem administrar servidor, e como permitir o acesso remoto?

1RDS: o banco sem o servidor

Você usa o banco. A AWS cuida do resto.

O RDS (Relational Database Service) é um serviço gerenciado de bancos relacionais (MySQL, PostgreSQL, MariaDB, Oracle, SQL Server). "Gerenciado" quer dizer que a AWS cuida da instalação, dos patches, dos backups e da infraestrutura. Por baixo, ele roda sobre uma instância EC2, mas você não acessa essa máquina: não há SSH nem sistema operacional.

2Criar e conectar: duas camadas de novo

"Acesso público" não abre a porta.

1 a 3. Criar a instância

RDS → Criar banco → mecanismo MySQL, modelo de nível gratuito (para não gerar custo), identificador (como db-instancia-xx-aws) e senha do administrador. Guarde a senha: ela não aparece de novo.

4. Acesso público: Sim

Sem isso, o banco só é alcançável de dentro da VPC, e o seu computador não chega nele.

5 a 7. Security Group e nome do banco

Use o Security Group padrão e, em "Configuração adicional", já crie a base inicial (no exercício, dbalpha).

8. Copiar o endpoint

Com a instância "Disponível", copie o endpoint: é o "endereço" do banco, no lugar de um IP.

9. Liberar a porta 3306

No Security Group, uma regra de entrada TCP na porta 3306 (a do MySQL). Sem ela, o cliente fica tentando e dá timeout.

10 e 11. Conectar e criar a tabela

No MySQL Workbench: nova conexão com o endpoint, porta 3306, usuário e senha. Depois crie a tabela direto na base remota.

12. Excluir a instância

Ao terminar: RDS → selecionar → Ações → Excluir. Instância ligada consome crédito do laboratório, igual à EC2.

Combine as duas camadas e veja quando a conexão funciona:

Cuidado: o que o slide faz por didáticaLiberar a 3306 para 0.0.0.0/0 expõe o banco à internet inteira, e qualquer robô pode tentar adivinhar a senha. Em produção, a origem deve ser só o seu IP (a opção "Meu IP" do console) ou só as instâncias da aplicação, e o banco nem deveria ter acesso público. É o risco de portas expostas da apostila de Cibersegurança.

3O exercício: a tabela projetos

O mesmo DDL da apostila de Bancos de Dados, agora numa base de nuvem.

O exercício pede a base dbalpha e a tabela projetos com idProjeto, sigla, dtInicio e dtTermino, e alguns registros. Uma solução (em SQLite aqui; no MySQL do RDS o idProjeto seria INT AUTO_INCREMENT PRIMARY KEY):

CREATE TABLE projetos (
  idProjeto INTEGER PRIMARY KEY AUTOINCREMENT,
  sigla     VARCHAR(10) NOT NULL UNIQUE,
  dtInicio  DATE NOT NULL,
  dtTermino DATE,
  CHECK (dtTermino IS NULL OR dtTermino >= dtInicio)
);
INSERT INTO projetos (sigla, dtInicio, dtTermino) VALUES
  ('NEXA',  '2026-08-01', '2026-12-15'),
  ('ALFA', '2026-09-01', NULL),
  ('IRIS',  '2026-09-10', '2026-09-25');
SELECT * FROM projetos;

Note como as restrições do Capítulo 3 de Bancos de Dados fazem trabalho aqui: UNIQUE na sigla e um CHECK que impede um término anterior ao início.

4Fechamento do capítulo

Cola da prova

  • RDS: banco relacional gerenciado (patches, backups, infraestrutura). Sem SSH nem SO.
  • Conexão pelo endpoint, e não por IP.
  • Para conectar de fora: acesso público e regra de entrada TCP 3306 no Security Group. Duas camadas.
  • 0.0.0.0/0 na porta do banco só em laboratório. Em produção, só seu IP ou só a aplicação.
  • Exclua a instância ao terminar: ela consome crédito ligada.

Teste rápido

Pergunta 1

Seu cliente de banco fica tentando e termina em timeout, apesar de o acesso público estar 'Sim'. Qual a causa mais provável?

Acesso público dá um endereço alcançável, mas quem libera a passagem é o Security Group. Sem a regra, o pacote é descartado em silêncio.
Pergunta 2

O que o RDS faz por você que uma EC2 com MySQL instalado não faz?

Esse é o sentido de 'gerenciado': você usa o banco, e a AWS administra a infraestrutura.
Pergunta 3

Por que não se deve liberar a 3306 para 0.0.0.0/0 em produção?

O correto é restringir a origem ao seu IP ou às instâncias da aplicação.
