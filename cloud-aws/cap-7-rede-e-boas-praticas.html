1VPC: a sua rede dentro da AWS

Quando o RDS "só é alcançável de dentro da VPC", de que rede se fala?

A VPC (Virtual Private Cloud) é uma rede virtual isolada, só sua, dentro de uma região. Dentro dela você divide o espaço de endereços em sub-redes (subnets), cada uma em uma zona de disponibilidade.

PeçaPapel
Sub-rede públicatem rota para a internet por um Internet Gateway; abriga o que precisa ser alcançado de fora (um servidor web)
Sub-rede privadasem rota direta da internet; abriga o que não deve ser exposto (um banco)
NAT Gatewaydeixa recursos privados saírem para a internet (atualizações, por exemplo) sem que a internet entre neles
Security Groupfirewall da instância
NACLfirewall da sub-rede

É por isso que o banco "ideal" nem deveria ter acesso público: ele fica numa sub-rede privada, e só a aplicação (numa pública ou na mesma VPC) chega até ele.

2Security Group x NACL

Stateful ou stateless: a pergunta que cai em prova.

Security GroupNACL
Onde atuana instânciana sub-rede
Memóriastateful: se a entrada foi permitida, a resposta sai automaticamentestateless: entrada e saída são avaliadas separadamente; é preciso permitir as duas
Regrassó AllowAllow e Deny, avaliadas em ordem numérica
Padrãonega tudo que entra, até haver regraa padrão da VPC permite tudo
Um pedido chega na porta 443

O pacote passa primeiro pela NACL da sub-rede (regra de entrada) e depois pelo Security Group da instância.

A resposta volta

No Security Group (stateful) a resposta é liberada automaticamente, porque a entrada foi permitida. Na NACL (stateless) é preciso uma regra de saída que deixe a resposta passar.

Na prática

A maior parte das pessoas configura só os Security Groups e deixa a NACL no padrão. A NACL é uma segunda camada, útil para bloquear um IP ou uma faixa inteira (algo que o Security Group, que só tem Allow, não faz).

3Boas práticas: arquitetura, custo e acesso

Uma lista curta que evita os erros mais caros.

Os pilares de uma boa arquitetura (AWS Well-Architected)

Excelência operacional

Automatizar, monitorar (CloudWatch) e aprender com falhas.

Segurança

Privilégio mínimo, criptografia, rastreabilidade (IAM, KMS).

Confiabilidade

Recuperar-se de falhas: várias AZs, backups.

Eficiência de desempenho

Usar o tipo de recurso certo e escalar com a demanda.

Otimização de custos

Pagar só pelo que precisa; desligar o que sobra.

Sustentabilidade

Reduzir o impacto energético do que se executa.

Acessando por código

# CLI: listar os seus buckets
aws s3 ls

# Python com boto3: o mesmo, por código (as credenciais vêm da role ou da configuração local)
import boto3
s3 = boto3.client("s3")
for b in s3.list_buckets()["Buckets"]:
    print(b["Name"])

4Fechamento da apostila

Cola da prova

  • VPC: sua rede virtual isolada. Sub-rede pública (rota para a internet) x privada (sem rota direta). NAT permite sair sem deixar entrar.
  • Security Group: instância, stateful, só Allow. NACL: sub-rede, stateless, Allow e Deny.
  • Seis pilares: excelência operacional, segurança, confiabilidade, desempenho, custo e sustentabilidade.
  • CLI e boto3 acessam a AWS por código; prefira roles a chaves.
  • Termine instâncias, exclua bancos, feche portas, alerte o orçamento.

Teste rápido

Pergunta 1

Qual a diferença central entre Security Group e NACL?

Stateful: a resposta de uma conexão permitida volta sozinha. Stateless: cada sentido é avaliado separadamente.
Pergunta 2

Onde o ideal é colocar um banco de dados?

Quanto menos exposto, melhor. A aplicação chega ao banco por dentro da VPC.
Pergunta 3

Qual a causa mais comum de conta de nuvem inesperadamente alta?

Instância, banco e IP elástico ociosos continuam gerando custo. Desligue o que não usa e use alertas de orçamento.
