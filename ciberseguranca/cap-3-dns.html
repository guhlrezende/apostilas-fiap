1DNS: de nome para endereço

A agenda de contatos da internet.

O DNS (Domain Name System) é o sistema que aponta nomes de domínio para endereços IP. Sem ele, você teria de decorar o IP de cada site. É uma hierarquia de servidores organizada em árvore, e nenhum servidor sozinho sabe tudo. Ao digitar um endereço, o computador faz uma consulta DNS: pergunta ao servidor DNS mais próximo, que responde com o IP ou encaminha a pergunta a outro servidor que possa saber.

Os três níveis (e o que cada um sabe)

1. Raiz

Não conhece os sites: conhece quem cuida de cada TLD (.com, .org, .br...). (Há 13 identidades de servidores raiz, cada uma replicada em centenas de locais.)

2. TLD

O servidor do domínio de topo (.com, .br). Conhece quem é autoritativo para cada domínio sob ele.

3. Autoritativo

Guarda os registros finais do domínio e responde diretamente. É o fim da cadeia: tem o IP de verdade.

CuidadoÉ comum ver os três níveis descritos com o mesmo texto, como se todos guardassem "os TLDs". Não é: raiz conhece os TLDs, TLD conhece os autoritativos, autoritativo tem o IP final.

2A consulta, passo a passo

Descobrir www.exemplo.com.br numa cache vazia.

1. Você pergunta ao resolvedor

O navegador pergunta ao resolvedor (o servidor DNS configurado, geralmente o do provedor ou um público): "qual o IP de www.exemplo.com.br?". Antes, ele confere o cache: se já sabe e a resposta ainda é válida, responde na hora e acabou.

2. O resolvedor consulta a raiz

Sem cache, ele pergunta a um servidor raiz. A raiz não sabe o IP, mas responde: "para .br, pergunte a estes servidores".

3. Consulta ao TLD

O servidor de .br também não sabe o IP, mas sabe quem é autoritativo por exemplo.com.br e indica.

4. Consulta ao autoritativo

O servidor autoritativo tem o registro A e responde com o IP.

5. A resposta volta e vai para o cache

O resolvedor devolve o IP ao seu computador e guarda a resposta pelo tempo do TTL. A próxima pessoa que perguntar a mesma coisa recebe a resposta pronta.

3Registros, cache e tipos de DNS

O "registro DNS" é a informação guardada no servidor autoritativo.

RegistroO que fazExemplo
Aaponta um nome para um endereço IPv4exemplo.com → 203.0.113.7
AAAAaponta um nome para um endereço IPv6(complemento)
CNAMEcria um alias: um nome que aponta para outro nomewww → exemplo.com
MXdiz qual servidor de e-mail recebe as mensagens do domínioexemplo.com → mail.exemplo.com
NSindica os servidores de nomes autoritativos do domínio
TXTguarda texto livre: verificação de domínio, chaves públicas, regras anti-spam
  • Cache DNS: armazena respostas recentes para acelerar as consultas seguintes, sem precisar perguntar ao autoritativo toda vez. Cada resposta tem um TTL (tempo de vida); ao expirar, é perguntada de novo. É por isso que uma mudança de DNS leva tempo para "propagar".
  • DNS público (Google 8.8.8.8, Cloudflare 1.1.1.1, OpenDNS): servidores abertos a qualquer pessoa, geralmente gratuitos. DNS privado: de uso interno de uma empresa ou organização, que controla os nomes da própria rede.

Duas ferramentas do dia a dia (ARP e tracert)

nslookup google.com      # pergunta ao DNS (Windows, Linux e macOS)
arp -a                   # mostra a tabela ARP: IP → MAC dos vizinhos da rede local
tracert google.com.br    # Windows  (traceroute no Linux/macOS): lista os roteadores do caminho

O ARP (Address Resolution Protocol) mapeia um IP ao MAC de um dispositivo na rede local: antes de falar com alguém, o host consulta a própria tabela ARP e, se não houver entrada, envia um ARP Request. O tracert rastreia o caminho de um pacote até o destino e mostra os IPs de todos os roteadores intermediários, o que ajuda a achar onde há atraso ou falha.

Atividade prática da aula (no seu computador)Subir um servidor web local com python -m http.server 8080, capturar o tráfego com o Wireshark e observar o que passa em HTTP. Faça isso só na sua própria máquina e rede: capturar tráfego de terceiros sem autorização é crime. O Capítulo 4 usa essa prática para explicar o ataque.

4Fechamento do capítulo

Cola da prova

  • DNS traduz nome em IP, numa hierarquia: raiz (conhece os TLDs) → TLD (conhece os autoritativos) → autoritativo (tem o IP).
  • Registros: A (IPv4), AAAA (IPv6), CNAME (alias), MX (e-mail), NS (servidores de nomes), TXT (texto/verificação).
  • Cache acelera; o TTL diz por quanto tempo a resposta vale.
  • Público (aberto a todos) x privado (interno de uma organização).
  • ARP: IP → MAC na rede local. tracert: mostra o caminho dos pacotes.

Teste rápido

Pergunta 1

Qual servidor DNS tem o registro final com o IP de um domínio?

A raiz indica o TLD, o TLD indica o autoritativo, e o autoritativo responde com o IP.
Pergunta 2

Para que serve o registro MX?

MX vem de Mail eXchange. O registro que aponta para um IP é o A, e o TXT guarda textos como verificações.
Pergunta 3

Por que uma mudança de DNS demora a 'propagar'?

Cada resolvedor reaproveita a resposta pelo tempo do TTL. Só depois que ela expira é que ele pergunta de novo e vê o valor novo.
