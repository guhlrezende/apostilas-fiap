Onde paramosNos capítulos anteriores o ESP32 só mandou sinais (OUTPUT). Agora ele lê: um botão. É o primeiro passo de uma lição maior: sensor é entrada, atuador é saída, e a lógica decide a ponte entre eles.

1O botão e o INPUT_PULLUP

Apertar dá LOW. Sim, ao contrário.

Um botão simples liga ou desliga um caminho elétrico. Se ele for ligado entre o pino e o GND, apertá-lo puxa o pino para 0 V. Mas e quando está solto? O pino fica "no ar", e um pino sem ligação definida flutua, captando ruído. A solução é o resistor de pull-up, que mantém o pino em HIGH quando nada o puxa. O ESP32 já tem um interno: basta pinMode(pino, INPUT_PULLUP).

Resultado: solto = HIGH, pressionado = LOW. A lógica fica invertida, e é o ponto que mais derruba quem está começando. O botão não precisa de resistor externo; o LED, sim. Complemento: no ESP32, os GPIOs 34, 35, 36 e 39 (só entrada) não têm pull-up interno; para um botão neles, use um resistor externo.

#define LED_PIN 26
#define BTN_PIN 21

void setup() {
  Serial.begin(115200);
  pinMode(LED_PIN, OUTPUT);
  pinMode(BTN_PIN, INPUT_PULLUP);       // entrada com pull-up interno
}

void loop() {
  if (digitalRead(BTN_PIN) == LOW) {    // LOW = botão pressionado
    Serial.println("Botão pressionado!");
    digitalWrite(LED_PIN, HIGH);
  } else {
    digitalWrite(LED_PIN, LOW);
  }
  delay(50);
}

Aqui as estruturas condicionais saem da teoria: o if/else decide a partir de uma leitura do mundo real.

2O preço do delay

Quando o processador dorme, o mundo continua.

Um código típico faz o LED piscar quando o botão é apertado, com delay(1000) duas vezes (aceso e apagado). Durante esses 2 segundos o ESP32 está "surdo": não lê o botão. Quanto isso custa? Complemento: millis() e debounceA saída é não bloquear: em vez de delay, guarde o instante da última ação e compare com millis() (milissegundos desde que a placa ligou):
unsigned long ultimo = 0;
const unsigned long INTERVALO = 500;
bool ledLigado = false;

void loop() {
  unsigned long agora = millis();
  if (agora - ultimo >= INTERVALO) {     // passou 500 ms?
    ultimo = agora;
    ledLigado = !ledLigado;
    digitalWrite(LED_PIN, ledLigado);
  }
  // o loop segue livre: dá para ler o botão a cada volta
}
O LED pisca igual, mas o loop() continua rodando e lendo o botão. E um botão mecânico "quica" por alguns milissegundos ao ser apertado (bounce), o que pode gerar vários cliques de um só: o debounce ignora mudanças muito próximas no tempo.

3Fechamento do capítulo

Cola da prova

  • Entrada: pinMode(pino, INPUT_PULLUP) e digitalRead(pino).
  • Com pull-up: solto = HIGH, apertado = LOW (lógica invertida). Sem pull-up, o pino flutua e lê valores aleatórios.
  • O botão não precisa de resistor externo com INPUT_PULLUP; o LED precisa do dele.
  • delay deixa o ESP32 surdo: toques entre leituras se perdem. Solução: millis() (complemento), e debounce para o 'quique' do botão.

Teste rápido

Pergunta 1

Com INPUT_PULLUP, qual o valor lido quando o botão está solto?

O resistor interno mantém o pino em HIGH; apertar liga ao GND e dá LOW.
Pergunta 2

O que acontece se você usar INPUT puro, sem resistor externo, com o botão solto?

Sem referência, o pino capta ruído. Por isso o pull-up.
Pergunta 3

Por que um delay(2000) no loop() faz o programa perder toques do botão?

O delay é bloqueante: nada mais roda enquanto ele espera.
