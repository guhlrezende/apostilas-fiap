Onde paramosNo Capítulo 1 você conheceu a placa. Agora o programa que roda nela: C++, uma linguagem compilada. Isso muda como os erros aparecem, e é o que este capítulo mostra, junto com as ferramentas do ambiente de desenvolvimento.

1Compilado x interpretado

Em C++, o programa inteiro precisa estar certo antes de rodar.

Em Python (interpretado), o código é executado linha a linha: se há um erro, o interpretador para e aponta a linha. Em C/C++ (compilado), um compilador converte o programa inteiro em código de máquina (um .exe no Windows; um .elf ou .bin para um ESP32). O código só é executado se compilar sem erros. O arquivo de programa de uma placa ESP32 usa a extensão .ino.

As três etapas do build

  1. Pré-processamento: as diretivas #include e #define são resolvidas antes de qualquer compilação (por exemplo, trazem as bibliotecas).
  2. Compilação: o código-fonte vira código-objeto.
  3. Linkagem: as bibliotecas usadas são vinculadas ao seu código e gera-se o binário final.

Escolha um erro e veja em que etapa ele aparece (ou se fica escondido):

Sempre salve o arquivoO compilador usa o arquivo salvo em disco, e não o que está na tela. Rodar sem salvar é rodar a versão anterior. É o erro mais bobo e um dos mais frequentes.

2O ambiente: VSCode, PlatformIO e Wokwi

Três ferramentas, cada uma com um papel.

FerramentaPapel
VSCodeEditor de código. Vira um ambiente de desenvolvimento conforme as extensões instaladas.
PlatformIO (extensão)O toolchain: baixa o compilador do ESP32 e o framework Arduino, resolve dependências e gera o binário (firmware.elf e firmware.bin).
Wokwi (extensão)O simulador: pega o binário do PlatformIO e o executa em uma placa ESP32 virtual, com Monitor Serial e os componentes desenhados em um arquivo de circuito.

PlatformIO compila, Wokwi simula. Sem compilar antes, o simulador não tem o que executar. (O Wokwi também tem uma versão web, ótima para começar, mas a execução local evita limites de tempo e deixa o projeto em arquivos que você versiona.) O Wokwi pede uma licença gratuita para a extensão local. Alternativas: a Arduino IDE, mais simples, ou uma placa física, que exige o toolchain instalado.

Os arquivos mínimos de um projeto

meu-projeto/
├── src/
│   └── meuProjeto.ino     # o código
├── platformio.ini         # placa, plataforma e framework
├── diagram.json           # o circuito virtual do Wokwi
└── wokwi.toml             # aponta o Wokwi para o binário compilado
# platformio.ini
[env:esp32]
platform = espressif32     # a família de chips (toolchain da Espressif)
framework = arduino        # usa a API Arduino: setup(), loop(), Serial, pinMode...
board = esp32dev           # placa genérica ESP32 DevKit

# wokwi.toml: a ponte entre as duas extensões
[wokwi]
version = 1
elf = ".pio/build/esp32/firmware.elf"
firmware = ".pio/build/esp32/firmware.bin"

No diagram.json ficam as peças e as ligações. Para o Monitor Serial aparecer, o circuito precisa ligar esp:TX a $serialMonitor:RX e esp:RX a $serialMonitor:TX. Sem essas duas ligações, o Serial.println() roda, mas você não vê nada.

4Fechamento do capítulo

Cola da prova

  • C++ é compilado: o programa inteiro precisa compilar antes de rodar. Python é interpretado, linha a linha.
  • Build em 3 etapas: pré-processamento, compilação, linkagem. Erros de lógica e esquecimentos só aparecem na execução.
  • VSCode edita, PlatformIO compila, Wokwi simula. Arquivos: .ino, platformio.ini, diagram.json, wokwi.toml.
  • Sempre salvar antes de compilar. Em dúvida, Clean e Build.

Teste rápido

Pergunta 1

Em que etapa aparece o erro 'DHT.h: No such file or directory'?

É o #include que falha, e ele é resolvido na primeira etapa do build.
Pergunta 2

Qual a função do PlatformIO neste ambiente?

O Wokwi simula; o PlatformIO compila. Sem compilar, o simulador não acha o firmware.
Pergunta 3

Você esqueceu o pinMode(pino, OUTPUT). O que acontece?

O compilador só pega erros de escrita. Esquecimentos aparecem no comportamento da placa.
