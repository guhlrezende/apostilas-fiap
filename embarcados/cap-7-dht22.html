Onde paramosO botão lê dois estados. O DHT22 lê números do ambiente, com uma biblioteca externa, risco de falha e a necessidade de decidir a partir do valor. É a síntese do que veio antes: pinos, tipos, printf, if e delay.

1Por que medir temperatura e umidade

Um problema real: conservar coisas sensíveis.

Acervos de livros antigos, remédios e alimentos estragam com calor e umidade fora da faixa. Um sistema IoT que mede e alerta é a solução óbvia: sensor, ESP32 e um alerta (LED, buzzer, mensagem). Os sensores mais comuns:

DHT11DHT22SHT40
Precisão (temperatura)±2 °C±0,5 °C±0,2 °C

O DHT22 liga com quatro pinos: VCC em 3,3 V, GND no GND, DATA em um GPIO e um pino NC (não conectado). UR é umidade relativa.

2O código, peça por peça

A primeira biblioteca externa do projeto.

A biblioteca da Adafruit entra no platformio.ini, e o PlatformIO a baixa sozinho no primeiro build:

lib_deps =
    adafruit/DHT sensor library @ ^1.4.6
#include <Arduino.h>
#include <DHT.h>

#define DHT_PIN 19
#define DHT_MODEL DHT22

DHT sensor(DHT_PIN, DHT_MODEL);          // objeto: pino e modelo

void setup() {
  Serial.begin(115200);
  sensor.begin();                        // inicializa o sensor
  delay(2000);                           // espera antes da 1ª medição
}

void loop() {
  float temp = sensor.readTemperature();
  float umid = sensor.readHumidity();

  if (isnan(temp) || isnan(umid)) {      // leitura falhou?
    Serial.println("Falha na leitura!!!");
    delay(2000);
    return;                              // encerra ESTA volta e tenta de novo
  }

  Serial.printf("Temperatura: %.2f  |  Umidade: %.2f\r\n", temp, umid);

  if (temp > 35) Serial.println("-- ALERTA -- Temperatura Alta!");
  if (umid > 65) Serial.println("-- ALERTA -- Umidade Alta!");

  delay(2000);                           // o DHT22 só lê a cada 2 s
}
  • DHT sensor(DHT_PIN, DHT_MODEL); cria um objeto da biblioteca. Daí em diante tudo é sensor.alguma_coisa().
  • isnan() (is not a number): quando a leitura falha, o sensor devolve NaN. Testa-se antes de usar o valor.
  • return dentro do loop() não para o programa: só encerra esta volta; o framework chama o loop() de novo.
  • O delay(2000) respeita o intervalo mínimo do DHT22. O delay dentro do bloco de erro evita tentar de novo antes de 2 s.
  • Dois if separados, e não if/else: os dois alertas podem ocorrer juntos.

3Índice de calor: o calor que se sente

Temperatura e umidade juntas valem mais que cada uma.

O índice de calor é a temperatura que o corpo sente: com o ar úmido, o suor evapora pior e o mesmo calor parece maior. A biblioteca já calcula:

float ic = sensor.computeHeatIndex(temp, umid, false);   // false = em Celsius
Exemplo resolvido: duas leituras e um limite de 25
24 °C e 40%: o índice de calor é cerca de 23,5 °C. Menor que 25, então o LED fica apagado.
27 °C e 60%: o índice sobe para cerca de 28,1 °C, acima da temperatura real, por causa da umidade. Maior que 25: LED aceso.
Para 32 °C e 70% o índice chega a cerca de 40,4 °C: a sensação é 8 °C acima do termômetro. (Valores calculados com a lógica da biblioteca da Adafruit: média de Steadman em valores baixos e regressão de Rothfusz acima de cerca de 80 °F. É complemento: a aula não detalhou a fórmula, e os decimais podem diferir da sua versão. A regressão de Rothfusz pura daria 25,3 para 24 °C e 40%, e não 23,5.)
Atividade para você: LED de alerta
Monte ESP32 + LED + DHT22 (por exemplo, DHT no GPIO 26 e LED no 25). Leia temperatura e umidade e mostre no Monitor Serial. Se as leituras forem válidas, calcule o índice de calor (ic).
Se ic > 25, acenda o LED e mostre o aviso com o valor. Depois de 3 segundos, apague o LED e meça de novo. Teste com valores acima e abaixo do limite.
Cuidado com o intervaloUm delay(2000) faltando antes do return do caso de erro faz o loop() pedir outra leitura na hora, antes dos 2 s que o DHT22 precisa. O resultado são falhas em série.

4De sensor a dataset

Medir é o primeiro passo de ensinar uma máquina.

Se cada leitura sair em uma linha CSV, o Monitor Serial vira uma fonte de dados: basta imprimir o cabeçalho uma vez e uma linha por leitura.

// globais, fora do setup() e do loop():
int id = 0;
String classe = "normal";   // o rótulo da linha: você decide como defini-lo
// no setup():
Serial.println("id,temperatura,umidade,classe");
// no loop(), a cada leitura válida:
Serial.printf("%d,%.2f,%.2f,%s\r\n", id++, temp, umid, classe.c_str());

Copiar a saída para um arquivo .csv e abri-lo com o Pandas leva ao mundo do machine learning, que usa o mesmo formato do conjunto Iris. A diferença é que aqui você cria o próprio conjunto, e a coluna de classe (o rótulo que diz o que cada linha representa) é sua responsabilidade: sem ela não existe classificação supervisionada. O valor de uma solução costuma estar em modelo próprio com dados próprios, e em saber explicar como os dados foram coletados.

5Fechamento do capítulo (e da apostila)

Cola da prova

  • DHT22: ±0,5 °C, −40 a 80 °C, leitura a cada 2 s. Pinos: VCC (3,3 V), GND, DATA (um GPIO), NC.
  • Biblioteca externa em lib_deps; objeto DHT sensor(pino, modelo); sensor.begin() no setup.
  • isnan() antes de usar a leitura; return encerra só a volta do loop.
  • Dois if separados para alertas independentes. Respeite o intervalo do sensor com delay.
  • Índice de calor junta temperatura e umidade (computeHeatIndex(t, u, false)). Saída em CSV leva ao dataset e ao machine learning.

Teste rápido

Pergunta 1

O que isnan(temp) testa?

Se o sensor falha, o valor é 'not a number'. O teste vem antes de imprimir ou comparar.
Pergunta 2

Qual o intervalo mínimo entre leituras do DHT22?

O DHT11 lê a cada 1 s; o DHT22, a cada 2 s.
Pergunta 3

O que o 'false' em computeHeatIndex(temp, umid, false) faz?

O terceiro argumento indica se a temperatura está em Fahrenheit; false significa Celsius.
