1O modelo: setup uma vez, loop para sempre

Você escreve duas funções; o framework as chama.

Todo programa de ESP32 no estilo Arduino tem as duas funções, e quem as chama é o framework, e não você. Na prática é como se o firmware fizesse:

setup();            // uma vez, logo depois de ligar ou reiniciar
while (true) {
  loop();           // repetidamente, enquanto houver energia
}
FunçãoQuando rodaPara quê
void setup()uma única vezinicializar: Serial.begin(), pinMode(), conexões, sensores
void loop()continuamenteoperar: ler sensores, decidir, acionar saídas, imprimir

Consequência prática: o valor que precisa sobreviver entre as voltas do loop() não pode ser declarado dentro dele. Variáveis declaradas dentro de uma função são locais (recriadas a cada chamada). Variáveis declaradas fora de qualquer função são globais e mantêm o valor.

2O Monitor Serial

Como a placa fala com você.

  • Serial.begin(115200) abre a comunicação serial a 115200 bits por segundo (a velocidade de comunicação). O Monitor Serial precisa estar configurado na mesma velocidade; senão aparecem caracteres aleatórios.
  • Serial.println(x) imprime e quebra a linha. Serial.print(x) imprime sem quebrar. Ambos aceitam texto e números.
  • Todo comando termina em ;: o compilador usa o ponto e vírgula, e não a quebra de linha, como delimitador.

Experimente: mude se a variável é global ou local, se a impressão quebra linha e o delay:

Exemplo resolvido: o contador que não conta
Código: void loop() { int id = 0; id = id + 1; Serial.println(id); delay(2000); }.
A cada volta, o int id = 0; roda de novo: id é recriado como 0, soma 1 e imprime 1. Sempre 1.
Correção: mover int id = 0; para fora do loop(), antes do setup(). Agora id é criado uma só vez, e o id = id + 1 acumula: 1, 2, 3...

3As quatro estruturas da lógica de programação

Sequência, decisão, repetição e função.

1. Instruções sequenciais

Executadas uma após a outra, na ordem, como uma receita.

int a = 5;
int b = 2;
int resultado = a + b;
2. Condicionais

Decisões a partir de uma condição.

int temperatura = 32;
if (temperatura > 30) {
  Serial.println("Ligue o ventilador.");
} else {
  Serial.println("Temperatura agradável.");
}
3. Repetição

Repete sem você escrever cada vez.

for (int i = 1; i <= 10; i++) {
  Serial.println("Flexão número " + String(i));
}
4. Funções

Um bloco com nome, chamado quando preciso.

void abrirPorta() {
  Serial.println("Girando a maçaneta...");
  Serial.println("Porta aberta!");
}
void setup() {
  Serial.begin(115200);
  abrirPorta();
}

É a mesma lógica que você usa em Python, com duas diferenças: chaves { } e ponto e vírgula em vez de indentação, e o programa é compilado, em vez de interpretado.

Uma regra de organizaçãoEm qualquer aplicação: (1) defina os sensores e atuadores; (2) atribua os pinos antes do setup() (#define LED 22 ou const int LED = 22;); (3) configure cada pino no setup(), com INPUT para sensor e OUTPUT para atuador. Trocar um pino fica sendo editar um só lugar.

4Fechamento do capítulo

Cola da prova

  • setup() roda uma vez; loop() repete para sempre. O framework chama as duas.
  • Serial.begin(115200) e o monitor na mesma velocidade. println quebra linha; print não.
  • Estado que sobrevive entre voltas do loop = variável global. Dentro do loop é local e é recriada.
  • Quatro estruturas: sequência, condicional (if/else), repetição (for) e função.
  • Organize: pinos antes do setup(), pinMode no setup(), uso no loop().

Teste rápido

Pergunta 1

Um contador declarado dentro do loop() imprime sempre 1. Por quê?

Variáveis locais vivem só durante a chamada. Para guardar o valor, declare fora do loop().
Pergunta 2

O Monitor Serial mostra caracteres aleatórios. Qual a causa mais provável?

As duas pontas da comunicação precisam usar a mesma velocidade.
Pergunta 3

Qual a diferença entre print e println?

Com print, as saídas ficam grudadas na mesma linha.
