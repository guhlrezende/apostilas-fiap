1Strings: mais do que aspas

Texto é uma sequência, e muito do que você aprendeu em listas vale aqui.

Uma str é uma sequência de caracteres: dá para indexar ("python"[0] é 'p'), fatiar ("python"[1:4] é 'yth') e percorrer com for. Mas ela é imutável: os métodos devolvem uma nova string, e a original não muda.

nome = "  Ana Souza  "
nome.strip()                 # 'Ana Souza'    (tira espaços das pontas)
nome.strip().upper()        # 'ANA SOUZA'
"sol,lua,mar".split(",")   # ['sol', 'lua', 'mar']
" - ".join(["a", "b"])      # 'a - b'
"banana".replace("a", "o") # 'bonono'
"banana".find("na")        # 2 (posição; -1 se não achar)
"python".startswith("py")  # True
"ana" in "banana"          # True
Erro comumEsquecer que strings são imutáveis: nome.upper() sozinho não muda nome. É preciso guardar: nome = nome.upper().

2Dicionários na prática

Contar, agrupar, achar por nome.

O padrão mais útil: contar ocorrências. O get(chave, padrão) evita o KeyError de ler uma chave que ainda não existe:

aluno = {"nome": "Ana", "idade": 19}
for chave, valor in aluno.items():     # percorre os pares
    print(chave, "=>", valor)
"idade" in aluno                       # True: testa se a chave existe
aluno.get("curso", "não informado")   # 'não informado' (sem erro)

3Erros: ler o traceback e tratar

Todo programa quebra. A diferença é saber ler o recado.

Quando algo dá errado, o Python imprime um traceback. Leia de baixo para cima: a última linha diz o tipo e o motivo do erro, e as de cima mostram o caminho até lá.

Traceback (most recent call last):
  File "ex.py", line 3, in <module>
    resultado = idade + "anos"
TypeError: unsupported operand type(s) for +: 'int' and 'str'
ErroQuando aparece
SyntaxError / IndentationErroro código está escrito errado (dois-pontos, parêntese, recuo)
NameErrorusou uma variável que não existe (ou errou o nome)
TypeErroroperação com tipos incompatíveis (int + str)
ValueErroro tipo está certo, mas o valor não serve (int("abc"))
IndexError / KeyErroríndice fora da lista / chave que não está no dicionário
ZeroDivisionErrordivisão por zero

4Arquivos e módulos

Guardar dados além do fim do programa, e usar código dos outros.

# escrever e ler um arquivo de texto
with open("notas.txt", "w", encoding="utf-8") as f:
    f.write("Ana;9.5\nBia;8.0\n")

with open("notas.txt", encoding="utf-8") as f:
    for linha in f:
        nome, nota = linha.strip().split(";")
        print(nome, float(nota))
  • Modos: "r" ler (padrão), "w" escrever (apaga o que havia), "a" acrescentar no final.
  • O with garante que o arquivo é fechado mesmo se der erro no meio.
  • Informe encoding="utf-8" para acentos não virarem símbolos estranhos.

Um módulo é código pronto que você importa. A biblioteca padrão já traz muito: math, random, datetime, csv, json. Bibliotecas de terceiros se instalam com pip install nome (por exemplo, pandas e numpy nas disciplinas de dados).

import math, random
math.sqrt(16)            # 4.0
random.randint(1, 10)    # inteiro aleatório de 1 a 10
Complemento: ambiente virtualCada projeto deve ter suas próprias bibliotecas, para versões diferentes não brigarem. O jeito padrão é um ambiente virtual: python -m venv .venv (e ativá-lo). E nunca versione essa pasta: ela entra no .gitignore (Capítulo 7).

5Escrever código que outras pessoas leem

Você vai ler seu código daqui a três meses, e vai parecer de um desconhecido.

  • PEP 8 é o guia de estilo oficial: nomes de variáveis e funções em minusculo_com_underline (snake_case), constantes em MAIÚSCULAS, 4 espaços de recuo, linhas curtas.
  • Nomes que dizem o que são: total_de_horas vence x.
  • Funções pequenas, que fazem uma coisa só.
  • Comentários explicam o porquê, e não o óbvio (# soma 1 não ajuda). Funções importantes ganham uma docstring, o texto entre aspas triplas logo abaixo do def.
  • Depurar: leia o traceback de baixo para cima; use print() para ver os valores; reduza o problema ao menor código que ainda erra.

6Fechamento da apostila

Cola da prova

  • Strings são imutáveis: os métodos (strip, split, replace) devolvem novas strings.
  • Dicionário: get(chave, padrão) evita KeyError; ótimo para contar.
  • Traceback: leia de baixo para cima. A última linha diz o tipo e o motivo.
  • try/except ValueError trata um erro previsto. Capture o específico.
  • with open(...) fecha o arquivo sozinho. "w" apaga; "a" acrescenta.
  • PEP 8, nomes claros, funções pequenas: escreva para quem vai ler.
