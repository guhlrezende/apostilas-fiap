1Uma API em 30 linhas

Quanto código é preciso para receber um JSON e devolver outro?

Com o FastAPI (biblioteca de Python), pouco. Você declara o formato dos dados numa classe, escreve uma função por rota e ele cuida de converter JSON, validar campos e devolver os códigos de erro certos. O exemplo recebe um pedido e decide a fila:

"""API mínima de triagem de pedidos (exemplo da apostila de AI Builder, cap. 6).

Rodar:  pip install fastapi uvicorn
        uvicorn api:app --reload
Abrir:  http://127.0.0.1:8000/docs  (a documentação interativa vem pronta)
"""
import os

from fastapi import FastAPI, Header, HTTPException
from pydantic import BaseModel

app = FastAPI(title="Triagem de pedidos")

# A chave vem do ambiente, nunca do código. Sem a variável, usa um valor de teste.
CHAVE = os.environ.get("API_KEY", "chave-de-teste")


class Pedido(BaseModel):
    cliente: str
    valor: float
    urgente: bool = False


@app.get("/saude")
def saude():
    """Rota que o monitoramento chama para saber se a API está de pé."""
    return {"status": "ok"}


@app.post("/triagem")
def triagem(pedido: Pedido, x_api_key: str = Header(default="")):
    """Recebe um pedido em JSON e devolve a fila para onde ele vai."""
    if x_api_key != CHAVE:
        raise HTTPException(status_code=401, detail="chave inválida")
    if pedido.urgente or pedido.valor >= 1000:
        fila = "prioridade"
    else:
        fila = "normal"
    return {"cliente": pedido.cliente, "fila": fila}

Três coisas do capítulo 1 aparecem aqui: a rota com método (@app.post("/triagem")), a validação do corpo (a classe Pedido; faltou campo, o FastAPI responde 422 sozinho) e a chave lida do ambiente.

Rodando com uvicorn api:app --reload, o endereço /docs abre uma documentação interativa gerada automaticamente, onde você testa cada rota sem escrever nada.

Como provar que a API faz o que diz?

Testes automáticos, que também servem de contrato.

2Testes: a prova de que funciona

A IA escreveu a API. Como você sabe que está certa sem testar na mão toda vez?

"""Testes da API de triagem. Rodar:  pip install pytest httpx  e depois  pytest -q"""
from fastapi.testclient import TestClient

from api import app

cliente = TestClient(app)
CAB = {"x-api-key": "chave-de-teste"}


def test_saude():
    r = cliente.get("/saude")
    assert r.status_code == 200
    assert r.json() == {"status": "ok"}


def test_pedido_grande_vai_para_prioridade():
    r = cliente.post("/triagem", json={"cliente": "Ana", "valor": 1500}, headers=CAB)
    assert r.json()["fila"] == "prioridade"


def test_pedido_pequeno_vai_para_normal():
    r = cliente.post("/triagem", json={"cliente": "Bia", "valor": 80}, headers=CAB)
    assert r.json()["fila"] == "normal"


def test_sem_chave_da_401():
    r = cliente.post("/triagem", json={"cliente": "Caio", "valor": 80})
    assert r.status_code == 401


def test_json_sem_campo_obrigatorio_da_422():
    r = cliente.post("/triagem", json={"cliente": "Davi"}, headers=CAB)
    assert r.status_code == 422

Resultado rodado na criação desta apostila: 5 passed. Cada teste fixa um comportamento: valor de 1.500 vai para prioridade, 80 vai para normal, sem chave dá 401, campo faltando dá 422. Se alguém (você ou a IA) mudar a regra sem querer, um teste quebra na hora. É a "verificação" do laço do capítulo 5.

Exemplo resolvido: a regra do limite
A regra diz valor >= 1000 vai para prioridade. E exatamente 1000?
Com >=, 1000 é prioridade. Se a IA "otimizar" para >, 1000 vira normal.
Os testes atuais usam 1500 e 80, então não pegariam essa mudança. Um bom teste a mais: valor: 1000 esperando prioridade. Limite é onde os bugs moram.

Docker e o nó HTTP do n8n.

3Empacotar e ligar no n8n

Como juntar as peças da trilha?

1. Empacotar

O Dockerfile do capítulo 4 já é desta API: docker build -t triagem .

2. Rodar com a chave

docker run --rm -p 8000:8000 -e API_KEY=minha-chave triagem. A chave entra por variável, nunca na imagem.

3. Chamar do n8n

Nó HTTP Request: método POST, URL http://SEU_HOST:8000/triagem, cabeçalho x-api-key vindo de uma credencial, corpo JSON com {{ $json.cliente }} e {{ $json.valor }}.

4. Decidir

Um Switch lê {{ $json.fila }} da resposta e segue o caminho certo.

localhost dentro de containerSe o n8n também roda em Docker, localhost dentro dele é o próprio container do n8n, não o seu PC. Coloque os dois serviços no mesmo compose.yaml e chame a API pelo nome do serviço (ex.: http://triagem:8000).

Teste rápido

Pergunta 1

O cliente manda {"cliente":"Davi"} com a chave certa. O que a API responde?

O campo valor não tem padrão na classe Pedido, então é obrigatório. O FastAPI recusa com 422 antes da função rodar.
Pergunta 2

Com a regra valor >= 1000, para onde vai um pedido de exatamente 1000?

Maior ou igual inclui o próprio 1000.
Pergunta 3

O n8n roda em Docker e chama http://localhost:8000, mas a API roda em outro container. O que acontece?

Cada container tem a sua rede. Use um compose com os dois serviços e chame pelo nome.
Pergunta 4

Onde a chave da API deve entrar no container?

Imagem pode ser compartilhada; o que está nela vaza junto. A chave entra só na execução.
